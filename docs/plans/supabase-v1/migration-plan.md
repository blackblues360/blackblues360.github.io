## 初次登录及各类数据

| 数据类别 | 规则 |
| --- | --- |
| 游客现有单键草稿 | 原键原文不写不删；用户明确选择“导入到当前账户”为新云文档，确认账户与预览后才写。拒绝导入仍可游客使用 |
| 已登录云端文档 | 按当前用户读取列表和正文；独立稳定UUID标识云文档，标题不是ID；本地缓存按用户隔离 |
| 未同步修改 | 保存原baseRevision、baseContent、pending；断网/退出不丢失，不转交下一账户，不以云端空列表覆盖 |
| 旧的已知v1变体 | 先保存原始文本备份，再规范化副本并展示差异，明确确认后上传；不写回原游客键 |
| 未知版本或损坏JSON | 停止导入，保留原文、提供下载与错误信息；绝不上传空板或sample SOP替代坏稿 |

整个导入不在登录回调自动运行。首次上传新UUID写入本地待同步记录，用户按一次导入可重试同ID；导入完成不自动删除本地原件。后续重新导入同文件没有内容hash去重保证，必须提示创建副本/选已有文档；不能仅凭文件名或实体ID判断同一文档。跨用户导入始终是显式新副本，不能复用其他用户的云ID。

孔板：读取原字符串→JSON.parse→备份原文→restoreState副本→比较规范化前后（丢失字段/标签/引用、裁剪数值、默认补值）→预览孔数、标题、标签/孔位分配→用户确认新建。现有图片无法恢复模型，不能承诺PNG/JPG迁移。完整state装入content，暂保留ui以兼容当前恢复；选择/highlight是否跨设备后续可改，不拆入全局偏好。

SOP：原始.soptime/草稿先备份，再走importDocument副本，检查环境迁移与布局裁剪差异，预览组/块/备注数量、时间/范围/富文本显示，用户确认新建。缺environmentRanges与显式[]区别保留；原始字段环境/实体ID不擅自删除。文档导出仍是原生v1对象，不把数据库信封/整数revision塞进.soptime；因此文件往返不自动关联原云文档，必须显式另存/选择替换目标，替换仍需目标expected_revision。无跨版本迁移规则，未来新增版本需单独经证据制定并测试。

4. 获得明确授权后才创建/配置云端资源和部署；本次不进行这些步骤。

单文件SQL失败时事务回滚该文件；不要继续下一文件。003失败时001/002可能已存在，但写授权仍关闭；先核查残留而不是一键重建。未有业务数据的隔离测试库可在用户同意后整体丢弃；正式环境已有数据时优先前向修复。回退前端到纯游客模式仍须提供原账户未同步内容导出，不清缓存。

本次不提供自动DROP脚本，以免误删真实数据。将来若必须撤销数据库：先冻结新写、备份与验证可恢复性；撤销RPC EXECUTE/业务GRANT，再移除RPC/触发器/约束与表的依赖。auth.users不由此迁移创建，禁止随业务回滚删除用户。备份保留期限、账户删除后备份清除与数据库恢复权限需要运营决策。
